# Plan: Fix Commission Workflow - Missing Execution Cycle Creation

## Problem Statement

When clicking "Beauftragen" (commission) in the Redaktionsplan:
1. ❌ The entry does NOT disappear from Redaktionsplan
2. ❌ The entry does NOT appear in Content-Erstellung Auftragsliste

## Root Cause Analysis

### The Missing Link: execution_cycles Table

The system has a **critical gap** in the commission workflow:

**What happens now:**
1. User clicks "Beauftragen" button → `editorial-columns.tsx:131`
2. Calls `handleCommissionContent(id)` → `editorial-planning.tsx:109`
3. Backend route `/api/agent-webhook/trigger` → line 40
4. Calls `updateKeyword(id, { Status: "Beauftragt" })` → `postgres.ts:456`
5. **Problem**: `updateKeyword()` has this code at line 532-534:
   ```typescript
   // Handle execution status updates
   if (updates.Status === 'Beauftragt' || updates.Status === 'In Arbeit' || updates.Status === 'Angeliefert') {
     // These are handled by execution cycles, not directly updatable
   }
   ```
6. **No execution_cycle record is created!**

**Why this breaks the workflow:**

The `mapToOldStatus()` function determines the visible status based on database tables:
```typescript
function mapToOldStatus(
  planning: typeof planningStatus.$inferSelect | null,
  execution: typeof executionCycles.$inferSelect | null,  // ← This is NULL!
  publishing: typeof publishingStatus.$inferSelect | null
): KeywordStatus {
  if (publishing?.status === 'published') return 'Published';
  if (publishing?.status === 'in_review') return 'Review';
  if (execution?.status === 'delivered') return 'Angeliefert';
  if (execution?.status === 'in_progress') return 'In Arbeit';
  if (execution?.status === 'commissioned') return 'Beauftragt';  // ← Never reached!
  if (planning?.status === 'planned') return 'Planned';  // ← Returns this instead
  return 'Backlog';
}
```

When `getKeywordMap()` queries the data:
- LEFT JOIN to `executionCycles` returns NULL (no cycle exists)
- `mapToOldStatus(planning, null, publishing)` is called
- Since `execution` is NULL, it can never return "Beauftragt"
- It returns "Planned" instead (because `planning.status === 'planned'`)
- Frontend filter: `keywords.filter(k => k.Status === 'Planned')` still matches
- Result: Item stays in Redaktionsplan

In Content-Erstellung:
- Filter at `creation/page.tsx:77`: `keyword.Status === 'Beauftragt'`
- Since status is "Planned", not "Beauftragt", the item is filtered out
- Result: Item does NOT appear in Auftragsliste

### Schema Architecture

The new schema requires a **3-table workflow** for execution:

1. **planning_status** (per URL)
   - `status: 'planned'` → Keyword is in Redaktionsplan
   - Updated when adding to planning

2. **execution_cycles** (per URL, per cycle)
   - `status: 'commissioned'` → Keyword is commissioned (Beauftragt)
   - `status: 'in_progress'` → Work has started (In Arbeit)
   - `status: 'delivered'` → Content delivered (Angeliefert)
   - **MUST be created when commissioning!**
   - `cycleNumber` increments for re-optimization

3. **publishing_status** (per cycle)
   - `status: 'in_review'` → Content in review (Review)
   - `status: 'published'` → Content published (Published)

## Solution: Create Execution Cycle on Commission

### Required Changes

#### 1. Create `createExecutionCycle()` Function

**File**: `/src/lib/postgres.ts`
**Location**: After `updateKeyword()` function (around line 570)

```typescript
/**
 * Creates a new execution cycle for a URL when commissioning content.
 * Automatically determines the next cycle number.
 */
export async function createExecutionCycle(
  urlId: string,
  actionType: 'Erstellung' | 'Optimierung',
  userId?: string,
  tenantId?: string
): Promise<number> {
  const tenant = tid(tenantId);
  return withTenant(tenant, async (tx) => {
    // Get next cycle number for this URL
    const [result] = await tx
      .select({ 
        maxCycle: sql<number>`COALESCE(MAX(${executionCycles.cycleNumber}), 0)` 
      })
      .from(executionCycles)
      .where(
        and(
          eq(executionCycles.urlId, urlId),
          eq(executionCycles.tenantId, tenant)
        )
      );
    
    const nextCycleNumber = (result?.maxCycle ?? 0) + 1;
    
    // Create new execution cycle
    const [cycle] = await tx
      .insert(executionCycles)
      .values({
        tenantId: tenant,
        urlId,
        cycleNumber: nextCycleNumber,
        actionType: mapFromOldActionType(actionType),
        status: 'commissioned',
        commissionedByUserId: userId || null,
        commissionedAt: new Date(),
      })
      .returning({ id: executionCycles.id });
    
    return cycle.id;
  });
}
```

**Simplest solution**: Add new helper function:
```typescript
export async function getUrlIdForKeyword(
  keywordId: string, 
  tenantId?: string
): Promise<string | null> {
  const tenant = tid(tenantId);
  return withTenant(tenant, async (tx) => {
    const [result] = await tx
      .select({ urlId: urlKeywords.urlId })
      .from(urlKeywords)
      .where(
        and(
          eq(urlKeywords.id, keywordId),
          eq(urlKeywords.tenantId, tenant)
        )
      )
      .limit(1);
    
    return result?.urlId ?? null;
  });
}
```
