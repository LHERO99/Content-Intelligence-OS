# Plan: HTML-Formatierung in der URL-Historie

Verbesserung der Darstellung von angeliefertem Content in der URL-Historie durch HTML-Rendering und CSS-Anpassungen für die Modal-Ansicht.

## Analyse
- Die Komponente `HistoryItem` in `src/features/shared/components/HistoryList.tsx` zeigt aktuell `log.Content_Body` als `whitespace-pre-wrap` Plain-Text an.
- Dieser Text enthält oft HTML (H1, Links, etc.), das aktuell nicht gerendert wird.
- In `package.json` sind `@tiptap/react` und `js-beautify` vorhanden, was auf eine Affinität zu strukturiertem Content hindeutet, aber für eine einfache Read-only-Anzeige in einem Pop-up ist `dangerouslySetInnerHTML` mit Tailwind's `prose` (sofern verfügbar) oder spezifischen CSS-Klassen am effizientesten.

## Geplante Änderungen

### 1. `src/features/shared/components/HistoryList.tsx`
- Ersetzen der Plain-Text-Anzeige durch ein `div`, das HTML rendert.
- Nutzung von `dangerouslySetInnerHTML` für `log.Content_Body`.
- Hinzufügen einer CSS-Klasse (z.B. `prose-sm` oder benutzerdefinierte Styles), um H-Tags innerhalb des Modals zu skalieren.

### 2. Styling (Inline oder Tailwind)
- Da es sich um ein Pop-up handelt, müssen wir sicherstellen, dass:
    - `h1`, `h2`, `h3` nicht das Layout sprengen (Größe reduzieren).
    - Links (`a`) blau/unterstrichen und klickbar sind.
    - Listen (`ul`, `ol`) korrekt eingerückt werden.
    - Padding/Margin für Block-Elemente angepasst wird.

## Detaillierte Schritte

1. **Komponente anpassen**:
   - In `HistoryItem` den Block in Zeile 81-83 ändern.
   - Von:
     ```tsx
     <div className="p-3 rounded-lg bg-muted/30 border border-border text-xs leading-relaxed whitespace-pre-wrap max-h-[200px] overflow-y-auto animate-in fade-in slide-in-from-top-1">
       {log.Content_Body}
     </div>
     ```
   - Zu:
     ```tsx
     <div 
       className="p-3 rounded-lg bg-muted/30 border border-border text-xs leading-relaxed max-h-[400px] overflow-y-auto animate-in fade-in slide-in-from-top-1 html-content"
       dangerouslySetInnerHTML={{ __html: log.Content_Body }}
     />
     ```

2. **CSS Definition**:
   - Hinzufügen von Styles in `HistoryList.tsx` (via styled-jsx oder Tailwind Utility Classes), um den Content zu bändigen:
     - `.html-content h1 { font-size: 1.25rem; font-weight: bold; margin-bottom: 0.5rem; }`
     - `.html-content h2 { font-size: 1.1rem; font-weight: bold; margin-bottom: 0.4rem; }`
     - `.html-content a { color: #00463c; text-decoration: underline; }`
     - `.html-content ul { list-style-type: disc; padding-left: 1.25rem; }`

3. **Verifizierung**:
   - Prüfen, ob der Content korrekt gerendert wird.
   - Sicherstellen, dass keine Styles aus dem Content das globale Layout beeinflussen (Scope).

## Risiken
- **XSS**: Da der Content aus der eigenen Datenbank kommt (angeliefert), ist das Risiko moderat, sollte aber bedacht werden.
- **Layout-Bugs**: Sehr große Bilder oder Tabellen im HTML könnten das Modal verbreitern. `max-width: 100%` für Bilder in `.html-content` wird hinzugefügt.
