# Plan: Optimierung der Performance-Daten-Speicherung

Dieses Dokument beschreibt die Umstellung der Performance-Daten-Speicherung von einer kombinierten Tabelle auf zwei spezialisierte Tabellen in Airtable, um Redundanzen zu reduzieren und die Performance-Analyse zu verbessern.

## Fehlerkorrektur (TypeScript Build-Error)

Der Deployment-Error wird durch eine verbleibende Referenz auf `TABLES.POTENTIAL_TRENDS` in einer Debug-Route verursacht, nachdem diese Konstante aus `airtable.ts` entfernt wurde.

### Schritte zur Fehlerbehebung:

1.  **Debug-Routen bereinigen**:
    *   `src/app/api/debug/trends/route.ts`: Diese Route ist nach dem Löschen der Trends-Tabelle obsolet. Sie sollte entweder gelöscht oder so angepasst werden, dass sie keine Fehler mehr verursacht (Rückgabe einer leeren Antwort).
    *   Überprüfung weiterer Debug-Routen auf veraltete Tabellen-Referenzen.
2.  **Middleware-Warnung**:
    *   Next.js weist darauf hin, dass die Datei `middleware.ts` (oder deren Konvention) veraltet ist. Dies ist eine Warnung, verhindert aber nicht das Build. Dennoch sollte geprüft werden, ob eine Umbenennung/Verschiebung gemäß der neuen Next.js Versionen sinnvoll ist (wobei dies hier zweitrangig gegenüber dem Build-Error ist).

### Zeitplan:
- [ ] Löschen oder Deaktivieren von `src/app/api/debug/trends/route.ts`.
- [ ] Suche nach weiteren Vorkommen von `POTENTIAL_TRENDS` oder `PERFORMANCE_DATA` im gesamten Projekt (`src/`).
- [ ] Verifikation des lokalen Builds (`npm run build`).
