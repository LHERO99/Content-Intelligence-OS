# Plan: Zeitraum-Filter für Content-Monitoring Detailansicht

Der Nutzer möchte in der Detailansicht des Content-Monitorings (`UrlDetail`) die Graphen für Performance und Ranking-Verlauf über einen Date-Picker filtern können.

## Analyse
- Die Komponente `UrlDetail` in `src/app/monitoring/url-detail.tsx` lädt Daten via `/api/monitoring/detail?url=...`.
- Die Daten enthalten Arrays für `urlPerformance` und `keywordRankings`, die jeweils ein `Date` Feld besitzen.
- Da kein komplexer Date-Picker (wie shadcn/ui date-range-picker) installiert ist, wird ein funktionaler, aber einfacherer Ansatz mit zwei HTML5 Date-Inputs (`input type="date"`) gewählt, um Abhängigkeiten minimal zu halten.

## Vorgeschlagene Änderungen

### 1. Zustandsverwaltung in `UrlDetail`
- Hinzufügen von `startDate` und `endDate` States.
- Initialisierung: `endDate` auf heute, `startDate` auf 3 Monate in der Vergangenheit (oder basierend auf den verfügbaren Daten).

### 2. UI-Komponente für den Filter
- Einbau einer Filter-Leiste oberhalb der Graphen-Sektion.
- Verwendung von `Input` Komponenten aus `src/components/ui/input.tsx` für die Datumsfelder.
- Button zum Zurücksetzen des Filters.

### 3. Clientseitige Filterung der Daten
- Erstellung von memoisierten Werten (`filteredUrlPerformance`, `filteredKeywordRankings`) basierend auf dem gewählten Zeitraum.
- Die Recharts `LineChart` Komponenten werden dann mit diesen gefilterten Daten gespeist.

## Detaillierter Implementierungsschritt

1.  **Imports erweitern**: `Input` und `Label` aus den UI-Komponenten importieren.
2.  **States definieren**:
    ```typescript
    const [dateRange, setDateRange] = useState<{ start: string; end: string }>({
      start: "",
      end: ""
    });
    ```
3.  **Initialisierung**: Sobald Daten geladen sind, `start` auf das kleinste Datum im Datensatz und `end` auf das größte setzen (falls nicht bereits manuell gesetzt).
4.  **Filter-Logik**:
    ```typescript
    const filteredPerformance = data.urlPerformance.filter(p => 
      (!dateRange.start || p.Date >= dateRange.start) && 
      (!dateRange.end || p.Date <= dateRange.end)
    );
    ```
5.  **JSX Anpassung**:
    - Vor dem Grid der Graphen eine `Card` oder ein `div` mit den beiden Inputs einfügen.
    - Labels wie "Von" und "Bis" hinzufügen.

## 5. UI-Überarbeitung der Monitoring-Seite (`/monitoring`)

Restrukturierung der Monitoring-Seite mit Tabs, KPI-Overview und Datepicker.

### Analyse
- Aktuelle Struktur: Eine Seite mit globalen Metriken oben und einer Tabelle unten.
- Ziel: Tabs wie in `/planning` (`Tabs`, `TabsList`, `TabsTrigger`).
- Tab 1: "KPI Overview" – Enthält die 4 Metrik-Karten und einen Datepicker für den Zeitraum.
- Tab 2: "Performance-Übersicht" – Enthält die durchsuchbare URL-Tabelle.
- Entfernen des "Daten aktualisieren" Buttons.

### Implementierungsschritte
1. **Zustand & Tabs**:
   - `activeTab` State hinzufügen (Default: "overview").
   - `dateRange` State für den globalen KPI-Filter hinzufügen.
2. **Tab-Struktur in `MonitoringPage`**:
   - `TabsList` mit den Triggern "KPI Übersicht" (`LayoutDashboard`) und "Performance-Liste" (`TableIcon`).
3. **Tab 1: KPI Overview**:
   - Verschieben der 4 `Card` Komponenten (Global Metrics) in diesen Tab.
   - Hinzufügen einer Filter-Leiste mit `Input type="date"` für Start- und Enddatum oberhalb der Karten.
   - (Optional) Die Metriken müssten idealerweise auf den Zeitraum reagieren (erfordert ggf. API-Anpassung oder clientseitige Berechnung, falls alle historischen Daten geladen werden). *Vorerst Fokus auf UI-Struktur.*
4. **Tab 2: Performance-Übersicht**:
   - Verschieben der URL-Performance Tabelle (`Card` mit `Table`) in diesen Tab.
   - Suchfunktion und "Optimierung planen" Funktionalität beibehalten.
5. **Detailansicht**:
   - Die `UrlDetail` Ansicht (wenn eine URL angeklickt wird) bleibt wie sie ist (mit dem bereits implementierten Datepicker), wird aber weiterhin die gesamte Seite einnehmen oder innerhalb des Performance-Tabs gerendert (Rücksprache mit dem Nutzer: Aktuell nimmt sie die ganze Seite ein, was sinnvoll erscheint).

### UI-Komponenten
- Icons: `LayoutDashboard`, `Table` (oder `List`).
- Tab-Styling konsistent zu `/planning` (bg-[#e7f3ee], active bg-[#00463c]).
