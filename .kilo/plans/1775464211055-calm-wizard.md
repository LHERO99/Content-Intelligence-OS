# Plan: Fix Blacklist Keyword-Only Entry

When a keyword is blacklisted, currently both the keyword and the URL are saved to the blacklist database. The user wants only the keyword to be saved if the blacklist type is "Keyword".

## Proposed Changes

### 1. `src/app/api/planning/blacklist/route.ts`

Modify the `POST` handler to conditionally omit `Target_URL` when creating a blacklist entry of type `Keyword`.

#### Case 1: Bulk move from Keyword-Map to Blacklist
*   Update the `addToBlacklist` call inside the loop.
*   If `Type` is `'Keyword'`, set `Target_URL` to `undefined` (or omit it).
*   *Note: We still want to preserve `Target_URL` for the history log to ensure the event is visible in the URL's history.*

#### Case 2: Single move from Keyword-Map to Blacklist
*   Update the `addToBlacklist` call.
*   If `Type` is `'Keyword'`, set `Target_URL` to `undefined` (or omit it).

#### Case 3: Direct add to Blacklist
*   This case already handles only `Keyword`, `Type`, and `Reason`.

## Verification Plan

1.  **Manual Test (Bulk Move):**
    *   Navigate to the Keyword Planning view.
    *   Select multiple keywords and click "Zur Blacklist hinzufügen".
    *   Select "Keyword" as the type.
    *   Verify (via logs or database inspection) that the new blacklist entries do NOT have a `Target_URL` set.
    *   Verify that the history log for the original URL still contains the "URL der Blacklist hinzugefügt" entry.

2.  **Manual Test (Single Move):**
    *   Select a single keyword and move it to the blacklist as type "Keyword".
    *   Verify that `Target_URL` is empty in the blacklist table.

3.  **Regression Test (URL Type):**
    *   Repeat the above but select "URL" as the type.
    *   Verify that `Target_URL` IS set in the blacklist table.
