# Plan: UI Zoom Adjustments for 100% Zoom Usability

The user reported that the application has "good usability" when the browser zoom is set to 80%, but lacks it at 100%. This typically indicates that elements are too large, there is too much padding/margin, or the layout becomes too cramped at the default 100% zoom level (likely on standard 1080p screens).

## Current Findings
- The application uses Tailwind CSS.
- `src/app/globals.css` currently sets `html { font-size: 110%; }` and `body { @apply ... text-lg; }`.
- `text-lg` in Tailwind is usually `1.125rem` (18px).
- Combined with `html { font-size: 110% }`, the base font size is approximately `16px * 1.1 * 1.125 = 19.8px`, which is significantly larger than the standard `16px`.
- Many components use fixed or relative spacing (`p-4`, `gap-6`, `h-[calc(100vh-120px)]`) which scales with this base font size.

## Proposed Changes
To simulate the 80% zoom look at 100% zoom, we need to reduce the base scale of the application.

### 1. Global Scale Reduction
Modify `src/app/globals.css` to reduce the base font size and body text size.
- Change `html { font-size: 110%; }` to `html { font-size: 90%; }` or `100%`.
- Change `body { @apply ... text-lg; }` to `body { @apply ... text-base; }` (16px) or even `text-sm` (14px) if `text-base` is still too large.
- Since the user likes 80% zoom, and the current effective base is ~123% (1.1 * 1.125), reducing it back to ~100% (or slightly less) should achieve the desired effect.

### 2. Spacing and Density Adjustments
If global scaling isn't enough, we will need to identify specific high-impact areas:
- **Layouts:** Check `AuthenticatedLayout` and main page containers for excessive padding (`p-6`, `p-8`).
- **Cards & Headers:** Reduce vertical padding in headers and cards.
- **Sidebar:** Check `AppSidebar` width and item spacing.

## Implementation Steps

1.  **Analyze `src/app/globals.css`:** Identify the current scaling factors.
2.  **Adjust `src/app/globals.css`:**
    - Set `html { font-size: 100%; }` (standard).
    - Set `body { @apply ... text-base; }`.
3.  **Audit `src/app/layout.tsx` and `src/components/authenticated-layout.tsx`:** Ensure there are no hardcoded large margins/paddings that prevent a dense layout.
4.  **Verification:** Since I cannot "see" the UI, I will rely on the mathematical reduction of sizes to match the "80% zoom" request.
    - Current: 110% (html) * 1.125 (text-lg) = 1.2375 (123.75% of browser default)
    - Target (80% of current): 1.2375 * 0.8 = 0.99
    - Proposed: 100% (html) * 1.0 (text-base) = 1.0 (100% of browser default)
    - This almost perfectly matches the 80% zoom preference.

## Potential Side Effects
- Some elements might become *too* small on very high-resolution screens without scaling, but standard browsers handle this better at 100% zoom than at 110%+ default.
- Specific fixed-size elements (icons, etc.) might need minor adjustments if they look out of proportion after the text size reduction.
