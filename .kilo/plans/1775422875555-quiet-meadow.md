# Plan: Fix n8n Content Log Integration

The user reports that n8n requests to `/api/planning/history` are failing when sending a specific JSON body containing HTML content and reasoning.

## Analysis
The failure is likely due to a mismatch between the field names sent by n8n and those expected by the API, or missing required fields.

### Key Observations:
1.  **Required Fields**: The API requires `finalKeywordId` and `finalActionType`.
    - In the n8n body: `keywordId` is provided (maps to `finalKeywordId`).
    - In the n8n body: **`status` is provided, but `actionType` or `Action_Type` is missing.**
2.  **Mapping Issues**:
    - `content` in n8n maps to nothing in the current API (which expects `contentBody` or `Content_Body`).
    - `reasoning` in n8n maps to nothing in the current API (which expects `reasoningChain` or `Reasoning_Chain`).
3.  **HTML Content**: Large HTML strings are generally fine in JSON, but if the API fails before reaching Airtable, it's likely a validation error in the route handler.

## Proposed Changes

### 1. Update `/api/planning/history/route.ts`
Enhance the field mapping to include common variations used by n8n:
- Map `content` to `finalContentBody`.
- Map `reasoning` to `finalReasoningChain`.
- Map `status` to `finalActionType` as a fallback (though `actionType` is preferred).

```typescript
    let { 
      keywordId, 
      Keyword_ID, 
      url, 
      Target_URL, 
      Logged_URL,
      actionType, 
      Action_Type, 
      status, // Added
      contentBody, 
      Content_Body, 
      content, // Added
      diffSummary, 
      Diff_Summary, 
      reasoningChain, 
      Reasoning_Chain, 
      reasoning, // Added
      editor, 
      Editor 
    } = body;

    // Standardize field names
    const finalKeywordId = keywordId || Keyword_ID;
    const finalUrl = url || Target_URL || Logged_URL;
    const finalLoggedUrl = Logged_URL || finalUrl;
    const finalActionType = actionType || Action_Type || status; // status fallback
    const finalContentBody = contentBody || Content_Body || content; // content fallback
    const finalDiffSummary = diffSummary || Diff_Summary;
    const finalReasoningChain = reasoningChain || Reasoning_Chain || reasoning; // reasoning fallback
```

### 2. Validation Improvement
The API currently returns a 400 if `finalActionType` is missing. Since n8n sends `status`, this is the likely cause of the failure.
