# Plan: Fix n8n Callback Validation Error

The user reports a 400 error from n8n with the message "Missing keywordId or content".

## Analysis
The error is coming from `src/app/api/n8n/callback/route.ts`, not the history route we previously updated. The n8n request is hitting the callback endpoint, which has its own validation logic.

### Key Finding:
In `src/app/api/n8n/callback/route.ts` (lines 25-30):
```typescript
const { keywordId, content, reasoning, status } = body;

if (!keywordId || !content) {
  console.error('[API] n8n callback missing fields:', { keywordId, content: !!content });
  return NextResponse.json({ error: 'Missing keywordId or content' }, { status: 400 });
}
```
If the `keywordId` or `content` fields are missing or empty in the parsed JSON body, it returns a 400. 

Wait, the user's log shows:
```json
{
  "keywordId": "recA1KB7NJwFIQFPc",
  "content": "<h1>Header Level 1</h1>..."
}
```
The fields *seem* to be there. However, the JSON in the error message shows:
`\"body\": \"{\\n \\\"keywordId\\\": \\\"recA1KB7NJwFIQFPc\\\",\\n \\\"content\\\": \\\"<h1>Header Level 1</h1>...`

One possibility is that `request.json()` is failing or the body is not being parsed correctly due to the complexity of the HTML or extra whitespace/newlines. Another possibility is that `keywordId` is being sent with a different casing or mapping that I missed.

Actually, looking at the user's provided JSON again:
```json
{
  "keywordId": "recA1KB7NJwFIQFPc",
  "content": "<h1>Header Level 1</h1>\n<p><strong>Auf dem letzten Hause eines kleinen Dörfchens</strong>..."
}
```
If n8n is sending the body as a string instead of actual JSON, or if the `Content-Type` header is not correctly handled, `request.json()` might behave unexpectedly. But the headers show `content-type: application/json`.

Let's improve the robustness of the callback handler.

## Proposed Changes

### 1. Update `src/app/api/n8n/callback/route.ts`
- Enhance the extraction of `keywordId` and `content` to handle potential casing issues (e.g., `Keyword_ID` or `contentBody`).
- Add better logging to see exactly what `body` contains when validation fails.
- Standardize the field mapping similar to the history route.

```typescript
    const body = await request.json();
    
    // Extract with fallbacks
    const keywordId = body.keywordId || body.Keyword_ID;
    const content = body.content || body.contentBody || body.Content_Body;
    const reasoning = body.reasoning || body.reasoningChain || body.Reasoning_Chain;
```
