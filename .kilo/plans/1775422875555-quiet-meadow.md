# Plan: Fix n8n Callback Validation Error

The user reports a 400 error from n8n with the message "Missing keywordId or content".

## Analysis
The user continues to receive a 400 error: "Missing keywordId or content", and the details show that both `keywordId` and `content` are evaluated as `false` (missing), despite being visible in the request log.

### Root Cause Hypothesis:
The `request.json()` call might be failing to parse the body correctly, or the body is being sent in a way that results in an empty object after parsing. This can happen with certain n8n configurations or if there's a character encoding issue with the large HTML block.

By switching to `request.text()` and manually parsing, we can log exactly what the server receives *before* parsing, which is crucial for debugging why the fields appear missing.

## Proposed Changes
1.  **Modify `src/app/api/n8n/callback/route.ts`**:
    *   Use `request.text()` instead of `request.json()`.
    *   Add a try-catch block for `JSON.parse()`.
    *   Log the raw body for debugging.
    *   Return `receivedKeys` in the error response to help the user see what the server *actually* sees.

## Verification Plan
1.  **Manual Test**: User triggers the n8n request again.
2.  **Log Inspection**: Check Vercel/Server logs for "n8n callback received raw body".
3.  **Build Check**: `npm run build`.
