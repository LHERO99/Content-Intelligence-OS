# Plan: Implement Branding Tab in Admin Section

The goal is to allow administrators to customize the application's logo, favicon, and primary color via a new "Branding" tab in the Admin area.

## 1. Data Schema & Storage
- **Airtable Config Table**: Use the existing `Config` table to store new keys:
  - `BRAND_LOGO_URL`: URL of the custom logo.
  - `BRAND_FAVICON_URL`: URL of the custom favicon.
  - `BRAND_PRIMARY_COLOR`: Hex code for the primary theme color (e.g., `#00463c`).
- **Airtable Library**: Use existing `getConfig` and `updateConfig` functions in `src/lib/airtable.ts`.

## 2. API Extensions
- **Update Config API**: `src/app/api/admin/config/route.ts` already supports GET/PATCH. Ensure it handles the new branding keys.
- **File Upload API**: Create a new endpoint `src/app/api/admin/branding/upload/route.ts` to handle logo/favicon uploads (suggest using Vercel Blob or a similar integrated storage if available, otherwise base64 in Airtable if small, but URL is preferred).

## 3. UI Components
- **Admin Page**: Add a "Branding" tab to `src/app/admin/page.tsx`.
- **BrandingTab Component**: Create `src/features/admin/components/branding-tab.tsx` containing:
  - **Color Picker**: A color input for `BRAND_PRIMARY_COLOR`.
  - **File Uploaders**: Drag-and-drop areas for Logo and Favicon.
  - **Preview**: Real-time preview of how the color and logo look.
  - **Save Button**: To persist changes to Airtable.

## 4. Global Application Styling
- **Dynamic Theme Provider**: Create a client component `src/components/providers/branding-provider.tsx` that:
  - Fetches branding config on mount (or receives it via props from Root Layout).
  - Injects CSS variables into `:root` (e.g., `--primary: #hex;`).
  - Updates the `<link rel="icon">` and logo `<img>` tags dynamically.
- **Tailwind Integration**: Update `tailwind.config.ts` to use the CSS variable for the primary color:
  ```ts
  theme: {
    extend: {
      colors: {
        primary: "var(--primary, #00463c)",
      }
    }
  }
  ```
- **Refactoring**: Replace hardcoded `#00463c` instances with `text-primary` or `bg-primary` where appropriate (staged over time or via bulk edit).

## 5. Implementation Steps
1. **Scaffold Branding Tab**: Add the UI to the Admin page.
2. **Setup Storage**: Implement a simple upload mechanism for images.
3. **Connect API**: Wire the Branding tab to the Config API.
4. **Theme Injection**: Implement the `BrandingProvider` to apply colors and logos globally.
5. **Verification**: Test color changes and logo updates across the app.

## 6. Open Questions
- **Storage**: Should we use Vercel Blob, Cloudinary, or store small assets directly in Airtable attachments? (Recommendation: Vercel Blob for simplicity in this environment).
- **Favicon**: Changing favicon dynamically requires updating the DOM link tag. Is this acceptable for the initial prototype?
