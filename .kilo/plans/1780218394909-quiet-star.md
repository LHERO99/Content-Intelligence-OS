# Plan: User-Anzeige in Content-Historie hinzufügen

## Ziel
Bei jedem Event in der Content-Historie soll angezeigt werden, welcher User die Aktion ausgeführt hat (Name und/oder E-Mail).

## Aktueller Stand

### ✅ Was bereits funktioniert
- **User-Tracking wird bereits erfasst**: Die `process_events` Tabelle hat ein `user_id` Feld
- **User-IDs werden gespeichert**: Bei den meisten Events wird `session.user.id` erfasst und in der Datenbank gespeichert
- **User-Daten sind verfügbar**: Die `users` Tabelle enthält alle User-Informationen (id, name, email, role)

### ❌ Was fehlt
- **Keine Anzeige der User-Namen**: Die aktuelle `getContentLogs()` Funktion holt nur die User-IDs, nicht die Namen
- **Kein JOIN mit users Tabelle**: Die Datenbankabfrage verbindet `process_events` nicht mit `users`
- **UI zeigt keine User-Information**: Die Frontend-Komponenten zeigen derzeit keine User-Information an

## Implementierungsplan

### 1. Backend: Datenbankabfrage erweitern

**Datei**: `/src/lib/postgres.ts`  
**Funktion**: `getContentLogs()` (circa Zeile 866-907)

**Änderungen**:
- LEFT JOIN mit `users` Tabelle hinzufügen auf `processEvents.userId`
- User-Felder (name, email) zur SELECT-Klausel hinzufügen
- Return-Typ erweitern um User-Informationen

**Begründung für LEFT JOIN**:
- Einige Events könnten keine User-ID haben (System-Events, alte Einträge)
- Bei gelöschten Users würde INNER JOIN die Events ausblenden
- LEFT JOIN stellt sicher, dass alle Events angezeigt werden

**TypeScript-Änderungen**:
```typescript
// Return-Typ erweitern
Editor?: string[];  // Bleibt für Backwards-Kompatibilität
UserName?: string;   // NEU: Name des Users
UserEmail?: string;  // NEU: E-Mail des Users
```

### 2. TypeScript-Typen aktualisieren

**Datei**: `/src/lib/postgres-types.ts`  
**Interface**: `ContentLog`

**Änderungen**:
- `UserName?: string;` hinzufügen
- `UserEmail?: string;` hinzufügen
- Existierendes `Editor?: string[];` beibehalten für Kompatibilität

### 3. Frontend: History-Komponente erweitern

**Datei**: `/src/features/shared/components/HistoryList.tsx`

**Layout-Struktur (ANGEPASST)**:
```tsx
<div className="space-y-1.5">
  <div className="flex items-center justify-between gap-4">
    {/* LINKS: Event Label + Version Badge */}
    <div className="flex items-center gap-2 overflow-hidden">
      <span>{summary}</span>
      {version && <Badge>{version}</Badge>}
    </div>
    
    {/* RECHTS: Timestamp + User (vertikal gestapelt) */}
    <div className="flex flex-col items-end gap-0.5">
      <span className="text-[10px] text-muted-foreground">
        {timestamp}
      </span>
      {(log.User_Name || log.User_Email) && (
        <div className="flex items-center gap-1.5 text-[11px] text-muted-foreground">
          <User className="h-3 w-3" />
          <span title={log.User_Email}>
            {log.User_Name || log.User_Email}
          </span>
        </div>
      )}
    </div>
  </div>
  
  {/* Content-Bereich (falls vorhanden) bleibt unverändert */}
</div>
```

**Änderungen**:
1. Timestamp und User werden in einem `flex-col` Container gruppiert
2. `items-end` sorgt für rechtsbündige Ausrichtung beider Elemente
3. User-Icon und Name erscheinen direkt unter dem Timestamp
4. Kleiner vertikaler Abstand (`gap-0.5`) zwischen Timestamp und User
5. Tooltip auf User-Name zeigt E-Mail bei Hover

**Anzeigeformat**: 
- Nur Name mit Email-Tooltip (kompakt, aber alle Infos verfügbar)
- User-Icon für visuelle Klarheit
- Kein "System"-Fallback → Zeile wird einfach ausgeblendet wenn kein User vorhanden

## Technische Details

### Relevante Code-Bereiche

**Database Schema** (`/src/lib/db/schema.ts`):
```typescript
process_events:
  - userId: text (FK zu users.id, ON DELETE SET NULL)
  
users:
  - id: text (PK, UUID)
  - name: text (nullable)
  - email: text (not null)
  - role: text
```

**Aktueller Event-Mapping** (`/src/lib/postgres.ts`, Zeilen 774-809):
```typescript
'url_added_to_backlog': 'URL wurde dem Tool hinzugefügt'
'url_suggested': 'URL wurde dem Tab \'Vorschläge\' hinzugefügt'
'url_planned': 'URL wurde der Redaktionsplanung hinzugefügt'
'cycle_commissioned': 'Content wurde beauftragt'
'content_published': 'Content veröffentlicht'
'keyword_added': 'Keyword hinzugefügt'
```

### Session-Struktur (NextAuth)
```typescript
session.user: {
  id: string;              // User UUID
  name: string;            // Display Name
  email: string;           // E-Mail
  role: string;            // SuperAdmin | Admin | Editor | Viewer
  tenantId: string;        // Tenant UUID
  passwordChanged: boolean;
}
```

## Entscheidungen ✅ ALLE GEKLÄRT

### Frage 1: Anzeigeformat ✅
**Entscheidung**: Name mit Email-Tooltip
- Anzeige: "Max Mustermann" mit User-Icon
- Bei Hover: Tooltip zeigt E-Mail-Adresse
- Kompakt aber alle Infos verfügbar

### Frage 2: Fallback für fehlende User ✅
**Entscheidung**: Keine Anzeige (Zeile ausblenden)
- Wenn kein User zugeordnet: User-Zeile wird nicht gerendert
- Sauberer als "System" oder "Unbekannt"
- Historisch: Alte Events ohne User-Zuordnung werden nicht künstlich befüllt

### Frage 3: Position in der Tabelle ✅ ENTSCHIEDEN
Wo soll die User-Spalte erscheinen?

**Entscheidung**: Rechtsbündig unter dem Timestamp

```
[Event Label + Version Badge] ------------------- [Timestamp]
                                                   [User Icon + Name]
```

Dies sorgt für eine saubere visuelle Gruppierung von zeitlichen Informationen (wann + wer) auf der rechten Seite.

| Risiko | Wahrscheinlichkeit | Impact | Mitigation |
|--------|-------------------|---------|------------|
| Performance-Problem bei vielen Events | Niedrig | Mittel | LEFT JOIN ist effizient, Index auf user_id existiert bereits |
