### 4. Keywords für URL laden
**Datei**: `src/app/creation/ai-editor-workspace.tsx`
**Position**: Nach dem bestehenden useEffect (nach Zeile 83)

```typescript
// Load all keywords for this URL
useEffect(() => {
  if (!targetUrl) {
    setAllKeywords([keyword]); // fallback to just the main keyword
    return;
  }
  
  setIsLoadingKeywords(true);
  fetch(`/api/planning/keywords/by-url?url=${encodeURIComponent(targetUrl)}`)
    .then(res => res.json())
    .then((keywords: KeywordMap[]) => {
      // Sort: main keyword first, then by keyword name
      const sorted = keywords.sort((a, b) => {
        if (a.Main_Keyword === 'Y' && b.Main_Keyword !== 'Y') return -1;
        if (a.Main_Keyword !== 'Y' && b.Main_Keyword === 'Y') return 1;
        return a.Keyword.localeCompare(b.Keyword);
      });
      setAllKeywords(sorted.map(k => k.Keyword));
    })
    .catch(() => {
      setAllKeywords([keyword]); // fallback on error
    })
    .finally(() => {
      setIsLoadingKeywords(false);
    });
}, [targetUrl, keyword]);
```

### 5. API Endpoint für Keywords by URL erstellen
**Neue Datei**: `src/app/api/planning/keywords/by-url/route.ts`

```typescript
import { NextRequest, NextResponse } from 'next/server';
import { getKeywordsByUrl } from '@/lib/postgres';
import { getTenantIdFromSession } from '@/lib/auth';

export async function GET(req: NextRequest) {
  try {
    const tenantId = await getTenantIdFromSession();
    const { searchParams } = new URL(req.url);
    const url = searchParams.get('url');
    
    if (!url) {
      return NextResponse.json({ error: 'URL parameter required' }, { status: 400 });
    }
    
    const keywords = await getKeywordsByUrl(url, tenantId);
    return NextResponse.json(keywords);
  } catch (error) {
    console.error('Error fetching keywords by URL:', error);
    return NextResponse.json({ error: 'Failed to fetch keywords' }, { status: 500 });
  }
}
```

## Design-Überlegungen

### Visuelle Hierarchie
1. **Tab-Leiste** (aktiv/inaktiv Tabs)
2. **Info-Section** (neue kompakte Bar)
3. **Content-Bereich** (Vorschau/Editor/AI-Chat)

### Farbschema
- Hintergrund: Gradient von `slate-50` zu `slate-100` für subtile Hervorhebung
- Badges: Weißer Hintergrund mit Primary-Border
- Haupt-Keyword: Primary-Farbe mit hellem Primary-Hintergrund (hervorgehoben)
- Neben-Keywords: Neutrales Grau für visuelle Hierarchie
- Text: Primärfarbe für wichtige Werte, Slate für Labels
- Icons: Primary-Farbe für Konsistenz

### Responsive Verhalten
- `flex-wrap`: Info-Badges brechen auf neue Zeile bei kleinen Bildschirmen
- `truncate` bei URL: Lange URLs werden abgeschnitten mit "..."
- `min-w-0` und `flex-1`: URL-Badge nimmt verfügbaren Platz ein

### Barrierefreiheit
- Klare Label-Text-Beziehungen
- Icons als visuelle Unterstützung
- Kontrastreiche Farben

## Alternative Design-Optionen

### Option A: Zwei-Zeilen-Layout mit Keyword-Badges ✅ (aktueller Vorschlag)
```
📄 Ziel-URL: www.example.com/solar-panels
🗺️ Keywords: [Solar Panels (Haupt)] [Solarmodule] [Photovoltaik] [...]
```
**Vorteile**: 
- Alle Keywords sichtbar
- Klare visuelle Hierarchie (Haupt-Keyword hervorgehoben)
- Kompakt aber gut lesbar
- Responsive durch Badge-Wrap

### Option B: Collapsible Keywords
```
📄 Ziel-URL: www.example.com/solar-panels
🗺️ Keywords (5): [Solar Panels (Haupt)] ▼ weitere anzeigen
```
**Vorteile**: Noch kompakter bei vielen Keywords, könnte später implementiert werden wenn >8 Keywords

### Option C: Nur Haupt-Keyword
```
📄 Ziel-URL: www.example.com/solar-panels
🗺️ Haupt-Keyword: Solar Panels
```
**Vorteile**: Maximale Kompaktheit, sehr schnell erfassbar (aber weniger Information)

**Empfehlung**: Option A - zeigt alle relevanten Keywords mit klarer visueller Hierarchie und erfüllt die Anforderung "alle Keywords anzeigen"
