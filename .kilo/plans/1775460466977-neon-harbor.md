# Problem Analysis
The server logs reveal that the request body is being received as a double-encoded JSON string (a string containing a JSON string). This causes `JSON.parse(rawBody)` to return a string instead of an object. When the code tries to access properties like `body.keywordId`, it fails because it's looking for properties on a string object, and the `receivedFields` log shows numeric indices (`'0'`, `'1'`, etc.), which are the character positions of the string.

Example log analysis:
- `bodyPreview: '"{\\n  \\"keywordId\\": \\"recA1KB7NJwFIQFPc\\",...'` (Note the extra quotes and escaped newlines/quotes).
- `receivedFields: ['0', '1', '2', ...]` (The string is being treated as an array of characters).

This typically happens when n8n (or the sending service) sends a JSON string as a raw body with a `Content-Type: application/json` header, but the payload itself is already stringified once.

## Proposed Plan
1. **Fix JSON Parsing in `src/app/api/n8n/callback/route.ts`**:
   - Implement a "double-parse" check. If `JSON.parse()` returns a string, parse it again.
   - This ensures that even if n8n sends double-encoded JSON, the API can still extract the data.

2. **Improve Field Mapping**:
   - Map `body.Target_URL` from n8n to `log.Logged_URL` in Airtable.
   - Use `body.status` to help determine the `Action_Type` if present.

3. **Detailed Error Reporting**:
   - Improve the 400 error response to include more diagnostic information if parsing fails or fields are missing.
